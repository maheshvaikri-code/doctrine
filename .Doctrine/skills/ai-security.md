# Skill: AI Security Review

> The shared control backbone for reviewing **any AI deployment**. It carries the
> standards, the threat taxonomy, and the review method common to every AI system;
> the deployment-pattern packs (`domains/agentic-ai.md`, `conversational-ai.md`,
> `iot-ai.md`, `contact-center-ai.md`, `saas-ai.md`) overlay only their *distinct*
> control surface. Extends `skills/security.md` (general appsec) with the risks
> specific to models, prompts, agents, and training data.

## Scope

G5 security sign-off (`roles/security-reviewer.md` holds the veto) and G1 design for
any feature that calls a model, takes model-influencing input, or acts on model
output. Composes with `skills/privacy-compliance.md` (data) and `skills/ai-slop.md`
(reviewing AI-*generated* code, a different axis).

## The threat taxonomy (the review's spine)

1. **Prompt injection** — direct (user) and **indirect** (poisoned retrieved/agent
   content). The #1 LLM risk; untrusted text can become instructions.
2. **Sensitive-information disclosure** — system-prompt/secret/PII leakage in output.
3. **Insecure output handling** — model output used unsanitized in code/SQL/HTML/shell
   (LLM output is untrusted input to the next system).
4. **Excessive agency** — a model given more tool/permission scope than the task needs.
5. **Data/model-supply-chain** — poisoned training data, tampered/untrusted model
   weights, malicious datasets or plugins.
6. **Model DoS / cost** — unbounded generation, token/context exhaustion, runaway loops.
7. **Model theft / extraction** — weights exfiltration; query-based model/data extraction.
8. **Overreliance** — acting on hallucinated output without verification or a human check.

## Review method (deterministic, at G1 + G5)

1. **Data-flow the trust boundaries:** where does untrusted text reach the model, and
   where does model output reach a consequential action? Both are attack surfaces.
2. **Treat model output as untrusted** — validate/encode before it touches code, a
   query, a filesystem, or another agent.
3. **Least agency:** the model gets the *minimum* tools/permissions/data; high-impact
   actions are gated (a §5 escalation / human-in-the-loop; enforce with an action-enforcement layer where wired).
4. **Isolate prompts + secrets** from user-controllable content; never put a secret
   where a prompt-injection can read it back.
5. **Bound cost + autonomy:** rate/token/loop limits (the v0.6.35 budget gate + loop
   caps), circuit breakers, kill switch.
6. **PII discipline:** no PII/secret to a third-party model without a signed DPA/BAA
   and redaction (see the regulated-domain packs).
7. **Evidence, not vibes:** adversarial test the guardrails (injection/jailbreak
   corpus), don't assert them — a guardrail you didn't try to break is decoration.

## Do

- Classify the EU-AI-Act tier and pick the deployment pack at G0.
- Red-team prompt injection / jailbreak with a real corpus; paste results.
- Log AI actions for non-repudiation (provenance; a provenance layer where wired).

## Don't

- Don't trust model output as safe, or a prompt as isolated, without proving it.
- Don't grant an agent standing high-impact permissions "for convenience."
- Don't send PII to an unvetted model or skip the injection/jailbreak test to ship.

## Review checklist (G5 AI-security exit)

- [ ] Trust boundaries mapped (untrusted-text-in, action-out)
- [ ] Model output validated/encoded before any consequential use
- [ ] Least agency: tool/permission/data scope minimized; high-impact actions gated
- [ ] Prompt-injection + jailbreak red-team run with pasted evidence
- [ ] Cost/loop/rate bounds + kill switch present
- [ ] PII/secret flows to models covered by DPA/BAA + redaction
- [ ] EU-AI-Act tier recorded; high-risk obligations addressed

## Common failure modes

Guardrails asserted but never attacked; model output piped into a shell/SQL/agent
unsanitized; an agent with broad standing tool access; secrets readable by a prompt;
"it's just a chatbot" ignoring indirect injection via retrieved content.
